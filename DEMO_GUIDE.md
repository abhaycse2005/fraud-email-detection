# Local Demo Guide

This guide uses the existing Flask project and its current data. It does not require retraining the model or resetting MongoDB.

## 1. Install

Open PowerShell in the project folder. If the project virtual environment is not already present, create it with Python 3.12 and install the requirements:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

If `.venv` already exists, keep using it. Do not replace an existing `.env` file. For a new setup only, copy `.env.example` to `.env` and configure the required values locally.

## 2. Configure services

The application requires a reachable MongoDB Atlas deployment. Set `MONGODB_URI` to the complete URI generated by Atlas. Standard `mongodb://` and SRV `mongodb+srv://` URIs are supported. Atlas access-list rules, database-user credentials, and the network connection must be valid. TLS verification uses certifi and stays enabled.

Gemini analysis requires a valid `GEMINI_API_KEY` with access and quota for the selected model. The model comes from `GEMINI_MODEL` and defaults to `gemini-3.1-flash-lite`. To select another model, set its exact model ID in the project `.env`, check that the same AI Studio project lists access and quota for it, then restart Flask. The setting does not automatically switch models or verify access. Keep the key in `.env`; never paste it into a presentation or terminal transcript.

Gmail is optional. To demonstrate it, configure the Google OAuth client ID and secret, the Gmail token encryption key, the authorized redirect URI, and the read-only Gmail API scope as described in [GMAIL_SETUP.md](GMAIL_SETUP.md). The Gmail account must complete OAuth consent.

## 3. Start the application

From the project root, run:

```powershell
.\.venv\Scripts\python.exe app.py
```

Open [http://127.0.0.1:5000](http://127.0.0.1:5000). Startup initializes Atlas before serving the app. If Atlas is unavailable, startup stops with a sanitized error. The app also starts its Gmail background worker; it checks connected accounts immediately. If automatic scanning is enabled for a connected account, startup can begin a real inbox scan. Disable automatic scanning before shutdown if you do not want it to run on the next startup. Do not run `gmail_worker.py` alongside `app.py`.

Keep the PowerShell window open during the demo. Press **Ctrl+C** to stop the app.

## 4. Register and log in

Use **Register** to create a demo account, then sign in. Accounts and history are stored in Atlas and are isolated by user. If the Atlas database already has an administrator, use that existing account; no default credentials are created by the app.

## 5. Analyze a message manually

Open **New Analysis** and enter a synthetic example, not private email. For example:

- Sender: `security@example.invalid`
- Subject: `Synthetic account notice`
- Body: `This demonstration message asks the recipient to reply with an account password to avoid account closure.`

Select **Analyze Email**. A completed Gemini analysis returns Safe, Suspicious, or Fraudulent with a confidence estimate and evidence. The confidence is not a calibrated probability. If Gemini is unavailable, the app reports an error and does not save or show a fabricated Safe result.

## 6. Connect Gmail (optional)

Open **Connect Gmail** and authorize the intended demo account. Confirm the consent page requests read-only mail access. Use a separate demo mailbox with synthetic messages when possible. Scanning reads message contents, sends them to Gemini for analysis, and saves completed results in Atlas history. The app does not send, delete, label, or modify Gmail messages.

## 7. Scan and watch progress

Select **Scan Gmail Now**. The scan uses 100-ID pages and Gmail API message batches of at most 50, reuses unchanged fingerprints, saves successful results immediately, and shows attempted, classified, failed, and deferred counts. Gemini requests remain sequential because the active project quota is not available locally. After repeated provider failures, remaining messages are deferred for a later retry; they are not classified as Safe and do not advance a failed page checkpoint.

Repeated clicks are protected by the per-user MongoDB scan lease. A scan can take time when many unique messages need Gemini analysis. Do not start another scan to speed it up.

## 8. Verify history and notifications

Open **History** and confirm the analyzed message has a saved result and explanation. **Explain Result** displays the stored explanation and does not make a second Gemini request. Incremental Fraudulent results can create a private in-app notification; historical scans do not create those notifications. Safe results do not create fraud alerts.

## Common troubleshooting

- **Atlas startup failure / server selection timeout:** verify the URI copied from Atlas, network access list, database user, DNS, and outbound access. Do not paste the URI into logs or chat.
- **Gemini quota, unavailable, timeout, or connection error:** check the model's active quota and API status in Google AI Studio. Failed analyses remain retryable; no Safe classification is substituted.
- **Gmail reconnect prompt:** reconnect through OAuth. Confirm the configured redirect URI and read-only scope; never share the stored token.
- **Deferred scan messages:** retry after the provider/network issue clears. The scanner will replay the failed page safely and reuse prior successful detections.
- **Page does not load:** confirm the Flask process is still running in PowerShell and use `http://127.0.0.1:5000`.
- **Missing Python package:** from the project root, run `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`.

## Demo checks before presenting

- Confirm Atlas is reachable and the configured Gemini model is available.
- Confirm the demo account is isolated from personal email and user data.
- Decide whether an automatic Gmail scan may run when the app starts.
- Use synthetic content for manual analysis and Gmail demonstrations.
- Keep `.env`, OAuth tokens, and API keys off screen and out of Git.
- Present actual scan progress and outcomes; do not describe deferred or untested integrations as successful.
